# Сервис подключения к тепловым сетям

> Обновление 0.2 уже реализовано. Актуальное состояние и запуск: [RELEASE-0.2.md](docs/RELEASE-0.2.md). Ниже сохранён первоначальный план; описания отсутствующих функций и инструментов относятся к старту проекта.

Старт проекта для команды из четырёх человек на две недели. Исходные материалы лежат в `Датасет/`. Они не изменялись.

## Что уже сделано

- Проверена структура предоставленного GeoJSON; найденные расхождения зафиксированы в `docs/DATASET_REVIEW.md`.
- Таблицы диаметров, габаритов и стоимости перенесены из технического приложения в `contracts/rules.json` автоматически.
- Подготовлены каркас Java 11 / Spring Boot 2.6.3, конфигурация PostgreSQL и Docker Compose.
- В каркасе реализованы только `GET /api/v1/meta` и `GET /api/v1/rules`.
- Подготовлены задачи участников, контракты модулей и план на 14 дней. Поиск маршрутов, загрузка через API, сохранение в БД и интерфейс ещё не реализованы.

## С чего начать каждому участнику

1. Прочитать `docs/DATASET_REVIEW.md` и `docs/CONTRACTS.md`.
2. Взять свою задачу из `docs/TEAM_PLAN.md`; готовые запросы для AI находятся в `docs/TEAM_PROMPTS.md`.
3. Работать в отдельной ветке. Общие контракты менять через интегратора, не копировать их в свой модуль.

## Запуск каркаса

На машине с запущенным Docker Engine и docker-compose 1.29.2:

```sh
docker-compose -p heatnet up --build
```

API: http://localhost:8080/api/v1/meta

Справочники: http://localhost:8080/api/v1/rules

Swagger: http://localhost:8080/swagger-ui/index.html

Параметр `-p heatnet` задаёт имя Compose-проекта явно, чтобы запуск не зависел от кириллицы в имени папки.

Локальная сборка без Docker требует JDK 11 и Maven:

```sh
cd backend
mvn test
mvn spring-boot:run
```

PostgreSQL нужен для следующего этапа хранения данных. Текущие два endpoint не обращаются к БД, поэтому успешный `/meta` не означает готовность БД или расчётного сервиса.

## Повторить аудит исходного файла

Python 3, без сторонних пакетов:

```sh
python tools/audit_dataset.py "Датасет/!!!_Датасет.geojson" --output docs/dataset-audit.json
python -m unittest discover -s tools/tests -v
```

Код завершения `2` означает найденные ошибки данных; `0` — отсутствие проверяемых ошибок структуры. Это локальный диагностический инструмент для файлов до 32 МиБ, а не потоковый импорт больших файлов сервиса. Он не проверяет пространственные расстояния и валидность полигонов.

## Состояние проверки окружения

На исходном рабочем компьютере обнаружены Java 8, отсутствие Maven в PATH и остановленный Docker Engine. Полная сборка Spring Boot и запуск Compose пока не проверены. JDK 11 предусмотрен в Dockerfile. Запуск на Ubuntu Server 22 и docker-compose 1.29.2 остаётся обязательной приёмкой.
