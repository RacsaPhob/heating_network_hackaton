# HackageCrew — варианты подключения к тепловым сетям ЗИЛ

Веб-прототип для кейса ЛЦТ 2026. Загружает GeoJSON, строит до трёх вариантов новых подключений, показывает их на карте, сравнивает стоимость и оценку, экспортирует GeoJSON и CSV. Исходный пример в `Датасет/!!!_Датасет.geojson` заменён на скорректированный набор организаторов (144 объекта, 17 точек подключения).

## Запуск

Нужен запущенный Docker Engine и Docker Compose. Из корня проекта:

```sh
docker compose -p heatnet-hackagecrew up -d --build
```

Открыть http://127.0.0.1:8080/ . Swagger: http://127.0.0.1:8080/swagger-ui/index.html . Остановить: `docker compose -p heatnet-hackagecrew down`. Данные PostgreSQL сохраняются в именованном томе. Для локальной разработки без Docker нужны JDK 11 и Maven; запуск: `mvn -f backend/pom.xml test`, затем `mvn -f backend/pom.xml spring-boot:run`.

Windows-скрипт `start.cmd` запускает тот же Docker Compose. Параметр `-Rebuild` пересобирает образ. Старый локальный Java-запуск через `.tools/` не требуется.

## Демонстрация

1. Нажать «Открыть конкурсный набор»; либо загрузить GeoJSON вручную.
2. Оставить демонстрационный режим для неполных входных сведений. Строгий режим может отклонить набор.
3. Нажать «Построить варианты», выбрать вариант справа и посмотреть карту, поиск и список неподключённых точек.
4. Открыть таблицу сравнения, проверить нарушения, скачать GeoJSON и CSV.

Проверенный расчёт на скорректированном наборе: первый вариант подключает 12 из 17 точек (2140,78 м, расходы на работы 273,75 млн ₽, штраф 562,66 млн ₽, итого для оценки 836,41 млн ₽, оценка 29,84). Автоматические проверки этого варианта прошли; пять точек остаются неподключёнными. Два других варианта подключают 14, но имеют нарушения по непрерывной длине участка и геометрии пересечения веток, поэтому не считаются допустимыми. Подробности в [документации сдачи](docs/SUBMISSION.md) и [матрице соответствия](docs/COMPLIANCE.md).

## Ограничения текущего прототипа

Приложение ограничено 20 МБ на входной файл, 4000 объектами и 100 точками подключения. Не проверена работа с требуемыми 3 ГБ входа, 500 МБ экспорта и 50 одновременными пользователями. Специальные переходы через препятствия и полноценная оптимизация всех ограничений не завершены. Полное соответствие ТЗ не заявляется.

Техническое приложение и разъяснения организаторов отменяют реконструкцию существующей сети. Каждая `oks_connection_point` считается отдельной целью; числовые ID исходного файла сохраняются как числа в ссылках результата. В 2D поля глубин имеют `null`. Именно эти актуальные правила использованы в расчёте.
